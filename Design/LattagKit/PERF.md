# PERF ・ 軽さの 記録(P11)

> 測り方:Release ビルド(DEBUG の 見本ルートだけ 有効)を シミュレータ(iPhone 17e)で 動かし、Home を 6秒 ながめた あとの `ps` の CPU%(2秒ごと 6回)。`sample` で 主スレッドの 上位を 確認。**実機の Instruments は 未計測(ユーザーの 作業)**。
> 見た目は 変えない:`scripts/snapall.sh` の score を 直す 前後で 比べた(H01 6.4 → 6.6、H03 7.9 → 7.9。差は 測定の ゆれ)。

| 場面 | 直す前 | 直した あと | 効いた 直し |
|---|---|---|---|
| Home を 10秒 ながめる(アイドル) | CPU 約 85〜93% | 約 9〜12% | ガラスの ふち(`LGGlassEdge`)の 角度グラデーションを 毎回 描くのを やめ、1回 作った 絵を 回転させる だけに |
| 同(メモリ) | 約 270MB | 約 360MB(DEBUG 見本写真の ぶん) | — |

## 効いた 直し(上位)
1. **ふちの 角度グラデーション**:`sample` で `argb32_shade_conic_RGB` + `atan2f`(CoreGraphics の ソフト描画)が 時間の 大半。画面に 10個 ちかい ふち × 傾きの 更新(60Hz)で 毎回 描きなおしていた → 絵を 1回 作って 回すだけ + 更新を 30Hz・0.4° 未満は 公開しない・バックグラウンドでは 止める(`DesignSystem/LGGlass.swift`)。
2. **写真の デコードを キャッシュ**:`HomeV64Host.makeInput` が 毎回 `UIImage(data:)` を やり直していた → `V64Images`(`NSCache`、表示サイズに 縮めて 読む)(`Today/V64/ImageCache.swift`)。
3. **ぼかしを 1回 だけ**:カード / レンズ / ページの 背景は、小さな 画像を 1回 ぼかして 保存し ひきのばす(押している 間の「ぼかし 15 → 5」は 強 / 弱の 2枚の クロスフェード)。粒子は 1枚の 絵を タイルに(2200回の 描画を やめた)。
4. 遠い ページ(いまの ±1 より 外)は 作らない(地球・粒子が 見えない 間は 動かない)。

## まだ 重い かも しれない 所(未対応・実機で 確認)
- ガラスの 影(`.shadow`)が 多い所(HomeV64View 15)。`compositingGroup` へ まとめる 余地。
- `AnyView` の ページ配列、下の 区画の `VStack`(`LazyVStack` に できる)。
- ライブドット / バッジの 30Hz `TimelineView` が 複数 ある。
