# P11 ・ アプリを 軽く する(見た目は 変えない)

> **使い方**:Claude Code に「`Design/LattagKit/prompts/P11_performance.md` を 読んで、その とおりに 進めて」と だけ 伝える。
> ルールは リポジトリの `CLAUDE.md`。**計画モードで 始める**。
> **いちばん 大事な 決まり:見た目 ・ 動き ・ バイブは モックの まま。重さ だけ 減らす。** 見た目が 変わる 直しは、やる前に ユーザーに 聞く。

## 0. すすめ方(この 順番を 守る)

1. **測る**(直す前の 数字を 取る)
2. **原因を 1つずつ 確かめる**(下の 表の 上から)
3. **直す → また 測る**(数字が 良く ならない 直しは 戻す)
4. 報告:どこが 何秒 / 何% 軽く なったか

推測で 一気に 書きかえない。1つ 直す たびに ビルドして 測る。

## 1. 測る(直す前)

- **Release で 測る**:Debug ビルド(Xcode から ▶ で 動かす)は 最適化が 無く、デバッガも つくので 何倍も 重い。`Edit Scheme → Run → Build Configuration = Release` か、Instruments(⌘I)で 測る。
- 実機(ユーザーの iPhone)で 測る。シミュレータは Mac の 力で 動くので 当てに ならない。
- Instruments で 取る もの:
  - **Time Profiler**:何に CPU を 使って いるか(メインスレッドの 上位 10)
  - **SwiftUI**(View Body / Updates):どの View が 何回 作り直されて いるか
  - **Animation Hitches**:カクつきの 回数
  - **Allocations / Leaks**:メモリが 増え続けて いないか
- 測る 場面:起動 → Home が 出るまで ・ Home で 10秒 何も しない ・ Home の 横スライド ・ 下へ スクロール ・ 撮影画面を 開く ・ Lattag yesterday を 開く ・ Mondo ページ。
- 結果を `Design/LattagKit/PERF.md` に 表で 書く(場面 / 時間 / CPU% / メモリ / カクつき回数)。

## 2. 疑わしい 所(上から 確かめる)

| # | 疑わしい 所 | 確かめ方 | 直し方(見た目は 同じ) |
|---|---|---|---|
| 1 | **写真の ぼかしを 毎フレーム 計算**(Home カードの 背景 ・ 友だちの ロック写真に `.blur(radius:)` を 大きな 画像の まま かけて、さらに ゆっくり 動かして いる) | Time Profiler で `blur` / `CoreImage` / `RenderBox` が 上位 | **48px の 小さな 画像を 1回だけ ぼかして 保存** → それを 引きのばして 表示(元から ぼけて いるので 見た目は 同じ)。動きは 画像を 動かす だけに する |
| 2 | **ガラス(`.glassEffect` / `.ultraThinMaterial`)の 重ね すぎ** | 画面の ガラスの 数を 数える(10枚 以上は 重い)・ スクロール中の カクつき | 重なって いる ガラスを `GlassEffectContainer` に まとめる。見えない 下の ガラスは 外す。小さな ピルは 半透明の 色 + ふちの 線で 十分か ユーザーに 確認 |
| 3 | **ずっと 動いて いる アニメ**(`repeatForever` ・ `TimelineView(.animation)` ・ 傾きの 光 ・ Mondo の 地球 ・ Ken Burns)が 画面の 外や 裏でも 動き続けて いる | 別の 画面を 開いた まま / アプリを 閉じた まま CPU が 下がらない | 画面に 出て いない とき(`onDisappear` ・ ページが 違う ・ `scenePhase != .active`)は **止める**。`TimelineView` は `.animation(minimumInterval: 1/30)`。Reduce Motion・低電力モード では 止める |
| 4 | **傾き(CoreMotion)で Home 全体が 作り直される** | SwiftUI instrument で Home の body が 1秒に 60回 | 傾きの 値は **光の レイヤー 1つ だけ** が 読む(小さな View に 分ける)。更新は 30Hz。値の 変化が 小さい ときは 更新しない |
| 5 | **状態の 持ち方**:大きな `ObservableObject` / `@Observable` 1つに 全部 入って いて、1か所 変わると 画面 全部が 作り直される | SwiftUI instrument の 更新回数 | 状態を 画面 ・ 部品 ごとに 分ける。時計(残り時間)は 表示する 小さな View の 中だけで 持つ。`AnyView` を やめる |
| 6 | **大きな 画像を そのまま 読む**(フル解像度を 小さな チェキや サムネに 使う ・ メインスレッドで デコード) | Allocations で 画像の メモリ ・ Time Profiler で `ImageIO` が メインスレッド | `CGImageSourceCreateThumbnailAtIndex` で **表示サイズに 縮めて から** 読む(バックグラウンド)。キャッシュの キーは 写真の ID(`hashValue` は 使わない)。`NSCache` に 上限 |
| 7 | **一覧が 全部 一度に 作られる**(`VStack` / `ForEach` の 中に 写真) | スクロールの 最初で 止まる | `LazyVStack` / `LazyVGrid`。チェキの 壁も 同じ |
| 8 | **影 ・ ぼかした 影の 重ね すぎ**(チェキ ・ カード ごとに `.shadow(radius:)` が 2〜3枚) | Time Profiler で `shadow` | 動かない 部品は `.drawingGroup()` か `.compositingGroup()` で まとめて 描く。影は 1枚に |
| 9 | **データの 取りすぎ**(Firebase の 監視が 多い ・ 閉じても 外して いない ・ 条件なしで 全部 取る) | 起動時の 通信 ・ リスナーの 数を ログで 数える | 画面が 消えたら 監視を 外す。`limit` を つける。同じ データを 2か所で 監視しない |
| 10 | **起動時に 全部 準備**(フォント ・ 写真 ・ 友だち ・ Mondo を 起動中に 読む) | 起動〜Home まで の 時間 | Home に 要る もの だけ 先に、残りは 後で(`Task` で 遅らせる) |
| 11 | **DEBUG だけの もの**(状態メニュー ・ 大量の `print` ・ ログ) | Release で 外れて いるか | `#if DEBUG` で 囲む。ループ内の `print` を 消す |

## 3. 守る こと

- **見た目 ・ 動き ・ バイブは 変えない**。どうしても 変わる 直し(例:ガラスを 減らす)は、前後の スクショを 並べて ユーザーに 聞いて から。
- 1つ 直す たびに `PERF.md` に「前 → 後」の 数字を 書く。良く ならなければ 戻す。
- 写真の 中身を 扱う 所(ロック中の 写真)は、48px の ぼかし画像 だけを 使う 決まりを 守る(はっきりした 写真を 早めに 読みこまない)。

## 4. 終わったら

- `PERF.md` に まとめ:場面ごとの 前 → 後、効いた 直し 上位 3つ。
- **git commit**(直し ごとに 分けて)。
- 報告:軽く なった 所 / まだ 重い 所 / ユーザーに 決めて ほしい こと。
