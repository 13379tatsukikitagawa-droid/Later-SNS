## 1. サーバーの 選び方 ── CloudKit で まかなえるか

### 結論

**友だち ・ フォロー申請 ・ フィード ・ チャット ・ グループの 23枚は、CloudKit だけでは 作らない。**
**Firebase(今 使っている Firebase Auth の 仲間)に 移す。**
CloudKit は「自分だけの 写真の 保管(ME ・ 1年 KEPT)」にだけ 使う(使わなくても よい)。

### CloudKit が 向かない 理由

| # | 必要な こと | CloudKit で できるか | 理由 |
|---|---|---|---|
| 1 | 友だち **だけ**に 写真を 見せる | ✕(安全に できない) | 公開データベースの 記録は 初期設定で アプリの 全ユーザーが 読める(Apple の 回答)。アプリの 画面で 隠しても、改造した アプリからは 読めて しまう |
| 2 | 友だち 人数 無制限 | ✕ | 共有データベース(CKShare)は 1つの 共有に 参加者 100人まで。友だちごとに 共有を 管理するのも 複雑 |
| 3 | 9:00 まで 見せない / 1日 23枚で 止める / 承認したら 両方を 友だちに する | ✕ | CloudKit には サーバー側で 動く プログラムが ない。端末の 時計を ずらすと 先に 見えて しまう。23枚の 上限も 同時に 撮ると 破られる |
| 4 | 申請・チャットの 通知 | △ | 通知の しくみは あるが、送る 相手を サーバーで 決められない |
| 5 | だれでも 使える | △ | iCloud に ログインしていない 人は 使えない。ログインは Firebase Auth なので、ID が 2つに なる |
| 6 | 容量・回数の 上限 | △ | ユーザー数に 応じて 増えるが、数字は 公開されていない(Apple の 回答) |

### 使う もの(Firebase)

- **Firebase Auth**: 今の まま。全部の ID を この `uid` に そろえる。
- **Cloud Firestore**(東京 `asia-northeast1`): ユーザー・友だち・申請・投稿の 情報・チャット・グループ。
- **Cloud Storage for Firebase**(同じ 東京): 写真。
- **Cloud Functions**(東京): 承認・9:00 の 解禁・23枚の 数え・通知・削除。
- **Firebase Cloud Messaging**: 通知(APNs 経由)。
- **App Check**(App Attest): 本物の アプリからの アクセスだけ 通す。
- **Firestore と Storage の セキュリティルール**: 「友だちか」「9:00 を 過ぎたか」を **サーバー側で** 判定する。Storage の ルールから Firestore を 読める(`firestore.get()` / `firestore.exists()`)ので、写真の ファイル自体を 友だち 以外に 渡さない。
- 料金プランは **Blaze(従量)**。Storage と Functions は Blaze が 必要。

### CloudKit の 残し方

- **自分の 写真の 保管だけ**、ユーザー本人の iCloud(private データベース)に 置いて よい(ME の 7日 ・ 1年 KEPT の カレンダー)。開発者の 費用は かからない。
- 今の CloudKit の グループ・招待リンクの 処理は、**新しい グループ(4章)が 動いてから 止める**。招待文の 形式(文面・`https://lattag.app/...` の 形)は そのまま 使う。
- 今 CloudKit に 本番ユーザーの データが ある 場合は、移行用の 画面を 1回だけ 出して Firebase に コピーする。テスト用の データだけなら 移行は しない。どちらか 先に 確認して 報告する。

## 2. 友だち(フォロー申請)

### 2-1. つながり方(BeReal と 同じ「相互」)

- A が B に **フォロー申請**を 送る → B が **承認** → **2人とも 友だち**に なる(片方だけの フォローは 作らない)。
- 友だちに なると、次の ことが できる。
  - おたがいの 写真が 見られる
  - チャットが できる
  - グループに 招待できる
- 画面の 言葉:
  - 送った 申請: `申請中`
  - 届いた 申請: `承認` / `あとで` / `削除`
  - 友だち: `友だち`
- **人数の 上限は なし**。今の 12人の 上限の コード・表示(`0/12` `3/12` `FRIEND 3/12` `12席の ダイヤル`)は **全部 消す**。
- **数は どこにも 表示しない**。友だち数・フォロワー数・申請数(赤い 点だけ)・いいね数。Profile の 統計の `FRIEND` の 欄も 消す(DAY STREAK / SHOTS / KEPT の 3つに する)。
- 解除: 友だちの Profile の `…` から `友だちを やめる`。相手には 通知しない。
- **ブロック**:
  - 相手から 見えなくなり、申請も 届かなくなる。
  - 写真・チャット・グループで 一緒に ならない。
  - 解除は 設定の「ブロックした人」から。

### 2-2. 友だちの 見つけ方

| 方法 | 内容 |
|---|---|
| **QR** | Profile の チェキ裏の QR を 読む → 申請画面(今の QR / Scan を 使う) |
| **リンク** | `https://lattag.app/u/<id>` を 共有 → 開くと 申請画面 |
| **ID で 検索** | `@yui_0612` を 完全一致で 検索。部分一致・おすすめの 一覧は 出さない(知らない人から 見つからない ように) |
| **連絡先**(任意) | 許可した 人だけ。電話番号は ハッシュに して 照合し、原文は 保存しない |
| **シェイク** | 近くで 2台を ふる → 申請(今の Shake を 使う) |

- **知らない人からの 申請を 減らす**: アカウントは 最初から 非公開で、名前と チェキ以外は 見えない。申請は 1日 30件まで(Functions で 数える)。

### 2-3. Friend 画面の 作りかえ(人数 無制限の 形)

- 12席の ダイヤルは、**「今日の 友だち」の 輪**に 変える。
  - 輪に 出すのは、最近 撮った 順の 友だち **最大 12人**。12人は 表示の 都合で、上限では ない。
  - 撮った 人は 緑の 輪。
- その 下に、**全員の 一覧**(名前順・検索欄つき)。
- 上に **届いた 申請**の 帯(あれば)。
  - 申請者の 丸と 名前を 横に 並べる。
  - 押すと `承認` / `あとで`。
- 見出しは `Friend` だけ。`0/12` などの 数は 消す。
- 申請・承認の 動きと バイブ:
  - 承認した とき: `success`。2人の キャラが くっつく 演出(今の `bumpBurst` を 使う)。
  - 申請を 送った とき: `pop` で、ボタンが `申請中` に かわる。

### 2-4. データ(Firestore)

```
users/{uid}                 名前・@id・チェキ画像の パス・タグ3つ・作った日・lastShotDay(最後に 撮った 日)
usernames/{id}              uid(@id の 重複を 防ぐ)
friendRequests/{from_to}    from・to・status(pending/accepted/declined)・createdAt
friends/{uid}/list/{fid}    since(友だちに なった 日)   ※ 両方向に 1件ずつ。作るのは Functions だけ
blocks/{uid}/list/{bid}     createdAt
```

- `friends` は **Functions だけが 書ける**(承認の 処理 `onRequestAccepted` で 両方に 同時に 作る)。アプリからは 読むだけ。
- 承認・解除・ブロックは Functions の `callable` で 行う(片側だけ 書き換えられない ように)。

## 3. 友だちの 写真(BeReal の 形)

### 3-1. 流れ(今の ルールを そのまま 友だちに あてはめる)

- 1日 3こま。撮った 写真は **翌朝 9:00 に 友だちに ひらく**。
- 友だちの きのうの 写真は、**今日 1枚 撮った 人だけ** 見られる(`shoot today to open`)。
- ひらく前は **ハッシュタグ と モザイク**だけ 見える。
- 7日で 消える。ME と 1年 KEPT に 残す 1枚は 本人の 端末(と 本人の iCloud)に 残る。

### 3-2. 画面の 置きかえ

- Lattag yesterday の タブを **`Friends` / `Mondo`** に する(`Groups` タブを `Friends` に 置きかえる)。タブバーは v54 の とおり Apple 純正の Liquid Glass。
- Friends タブの 中身(v54 の Groups タブの 形を 使う):
  1. ヒーロー: `Yesterday, together.` → **`Yesterday, friends.`**。統計は `To open / Left` だけ(人数は 出さない)。
  2. **友だちの 写真の フィード**(Mondo の `EVERYONE` と 同じ 2列 カード。名前・時刻の 印字・タグ)。
  3. ME カード。
  4. **Trips**(グループ)の 横カード(あれば)。
- Home の カメラの 4つの ボタン(v55)の 中身を 変える。
  - `FRIENDS`(人数を 出さず、`● 2 today` だけ)
  - `TRIP`(旧 NEW GROUP)
  - `MONDO`
  - `YESTERDAY` / `SHOOT` / `DEVELOP`(今の 条件の まま)
  - `CHAT` は 未読が あるとき だけ 出す。

### 3-3. データ と 守り方

```
posts/{postId}   owner・day(撮った 日 "2026-11-15")・openDay(ひらく 日 "2026-11-16")・openAt(その日 9:00 JST の 時刻)・expireAt(+7日)
                 tag・tm・blur(BlurHash 文字列)・w・h・paths{full,thumb}
Storage: posts/{owner}/{day}/{postId}_full.heic   _thumb.heic
```

- **Firestore の ルール**: `posts` を 読めるのは「本人」か、「本人の 友だち で ブロックしていない 人」だけ。
  ```
  allow read: if request.auth.uid == resource.data.owner
    || (exists(/databases/$(db)/documents/friends/$(resource.data.owner)/list/$(request.auth.uid))
        && !exists(/databases/$(db)/documents/blocks/$(resource.data.owner)/list/$(request.auth.uid)));
  ```
- **Storage の ルール**(写真の 中身を 守る):
  - 読めるのは 本人だけ。または、次の 3つが **全部 そろった** 人だけ。
    1. 友だちである(`firestore.exists(...friends...)`)
    2. 9:00 を 過ぎた(`request.time >= openAt`)
    3. 読む人が ひらく日 以降に 撮った(`firestore.get(users/<読む人>).data.lastShotDay >= openDay`。日付は "YYYY-MM-DD" の 文字なので 大小で 比べられる。9:00 区切りの 日付で 書く)
  - `openAt` は ファイルの カスタムメタデータにも 入れておく。
- `lastShotDay` は、写真の アップロード完了時に Functions が 書く(アプリからは 書けない)。
- 端末の 時計を ずらしても、サーバーの 時刻(`request.time`)で 判定するので 先には 見えない。
- 7日で 消す しくみ:
  - Firestore は `expireAt` に **TTL ポリシー**を 設定する。
  - Storage は バケットの **ライフサイクルルール**(作成から 8日で 削除)。
  - 毎日 1回 Functions で 取りこぼしを 消す。

## 4. チャット(つながった 友だち と)

- **友だち同士だけ**。友だちで ない 人・ブロックした 人とは 送れない(ルールで 止める)。
- 入口は 次の 3つ。
  - 友だちの Profile の `Chat`
  - 写真を 開いた 画面の 吹き出し
  - Home の `CHAT`
- 見た目と 機能は 今の グループの 部屋(チャット)を 1対1 に した 形。
  - 文字
  - 写真への 返信(写真の 上に 吹き出し)
  - タグの スタンプ
  - 既読(`既読` の 文字は 出さず、小さな 緑の 点で 示す)
- メッセージは **7日で 消える**(写真と 同じ。TTL)。

```
chats/{chatId}               members[2]・lastText・lastAt・unread{uid:数}   chatId = 小さい uid + "_" + 大きい uid
chats/{chatId}/messages/{m}  from・text・photoRef?・stamp?・createdAt・expireAt
```

- ルール: `request.auth.uid in resource.data.members`。作る時は 2人が 友だちか 確かめる(`exists(friends/...)`)。
- アプリは 開いている 部屋だけ リアルタイム(`addSnapshotListener`)で 読む。一覧は `chats` の 1件ずつ だけを 読む(メッセージ全部は 読まない)。
- 通知: `onMessageCreated`(Functions)→ FCM。ミュート中・その 部屋を 開いている 人には 送らない。

## 5. グループ = Trips(サブ機能 ・ 旅行や イベント用)

### 5-1. ルール

- **友だちの 中から** グループを 作る。人数は **今の 4〜8人の ルールを そのまま**。名前と 期間(例: 11/20〜11/23)は 任意。
- **1日 23枚を グループで 分けあう**。
  - だれが 何枚 撮っても よい。合計で 23枚に なったら、その日は おしまい。
  - 個人の 1日 3こまとは **別に 数える**(グループで 撮った 写真は 個人の 3こまを 減らさない)。
  - 撮影画面で グループを 選ぶと、カウンターが `23` から 減っていく(だれかが 撮るたびに 全員の 画面で 減る)。
- **解禁は 翌朝 9:00**。グループの 全員が、その日の 写真を まとめて ひらく(今の 現像 → 上映の 演出を 使う)。
- グループの 写真は **メンバーだけ**が 見られる。7日で 消える。メンバーは 「1年 KEPT」に 1枚 残せる。
- グループの チャットは 今の 部屋を そのまま 使う。
- 招待は 今の 招待リンクの 文面の まま。リンクを 開いた 人が 友だちで なければ、まず 友だち申請に なる。

### 5-2. 23枚を 正しく 数える

- アプリが 撮る **前**に `reserveGroupShot(gid)`(callable)を 呼ぶ。
  - Functions が トランザクションで `groups/{gid}/days/{day}.count` を 1 ふやす(23 未満の ときだけ)。
  - 成功したら アップロード先の パスと 番号(`7 / 23`)を 返す。
- Storage の ルール: そのパスに 書けるのは、予約した 本人で、予約から 10分以内 だけ。
- アップロードが 失敗・キャンセルした 予約は、10分後に Functions が 戻す(数を 1 へらす)。
- 同時に 撮っても 23枚を こえない(サーバーで 数えるため)。

```
groups/{gid}                      name・members[]・owner・from・to・createdAt
groups/{gid}/days/{day}           count(0〜23)・openAt
groups/{gid}/shots/{sid}          by・day・openAt・expireAt・tag・blur・paths
Storage: groups/{gid}/{day}/{sid}_full.heic  _thumb.heic
```

## 6. 写真を 軽く・速く する(お金を かけて よい 所)

### 6-1. 保存する 形

- 撮影後、端末で 2つ 作って アップロードする。
  - 長辺 **1600px** の HEIC(品質 0.7、約 250〜400KB)
  - 長辺 **400px** の サムネイル(約 25〜40KB)
- **BlurHash**(20〜30文字)を Firestore の 投稿に 入れる。ひらく前の モザイクと、読みこみ中の 表示に 使う(画像を 1枚も 落とさずに 出せる)。
- 位置情報などの EXIF は 消す(GPS は 必ず 消す)。

### 6-2. アップロード

- Firebase Storage の `putFile`(途中から 続きが できる 方式)を、バックグラウンドでも 続く 設定で 使う。
- 失敗したら 自動で 3回 やりなおす。電波が 悪い ときは 「あとで 送る」 列に 入れて、つながったら 送る。
- 撮った 写真は、アップロード中でも すぐ ME と 現像の 画面に 出す(端末の ファイルを 使う)。

### 6-3. 読みこみ

- 一覧は **サムネイルだけ**。全画面で 開いた とき だけ 1600px を 読む。
- 画像の キャッシュ(Nuke などの ライブラリ、ディスク 500MB)を 使い、**同じ 写真は 2回 落とさない**。
- 9:00 の 解禁の 直後は、全員が 一斉に 開く。
  - 9:00 前に、バックグラウンド処理(`BGAppRefreshTask`)と 無音の 通知で **サムネイルの パスだけ** 先に 取っておく(実行時刻は iOS が 決めるので、できた 時だけで よい)。
  - 9:00 に なったら 画像を 落とす。9:00 前には 画像そのものは 落とせない(ルールで 守られている ため)。
- 動画(Recap)は 端末の 中で 作り、サーバーには 上げない(共有する ときだけ 書き出す)。

### 6-4. 料金の めやす(東京の 料金は Google Cloud の 料金表で 必ず 確かめる)

| 使う人 | 写真の 保存(7日分) | 毎月の ダウンロード | めやす |
|---|---|---|---|
| 毎日 1,000人 | 約 10GB | 約 250GB | 月 数千円 |
| 毎日 10,000人 | 約 100GB | 約 2.5TB | 月 数万円(ほぼ ダウンロード代) |

- 計算の 前提: 1人 1日 3枚 ・ 友だち 20人 ・ サムネイルは 全部 見て、全画面は 3割だけ 開く。
- 費用の 大半は **ダウンロード**。サムネイルと キャッシュが 一番 効く。
- Firebase の コンソールで **予算アラート**(例: 月 1万円 ・ 3万円)を 設定する。
- Firestore の 読み取りを 減らす 工夫:
  - フィードは 1回 20件ずつ 読む。
  - 友だちの 一覧は 端末に 保存しておき、差分だけ 読む。

## 7. 安全(高校生の ユーザーが 多いので 必須)

- App Store の ガイドライン 1.2(ユーザーが 投稿する アプリ)に 合わせて、次の 4つを 必ず 入れる。
  - **報告**: 写真・チャット・ユーザーの `…` から
  - **ブロック**
  - **問い合わせ先**
  - **規約への 同意**: 初回の 設定で
- 報告は Firestore の `reports` に 入れ、Functions で 担当者に メールする。
- Mondo(世界に 出る 写真)は、出す 前に Cloud Vision の SafeSearch で 自動チェックする。
- アカウントは 最初から 非公開。知らない人は 名前と チェキしか 見えない。DM は 友だち同士 だけ。
- 退会したら、写真・チャット・友だち関係を Functions で 全部 消す(アカウント削除の 機能は App Store の 必須項目)。
- プライバシーの 説明(App Store の「App のプライバシー」)を 新しい 集め方に 合わせて 書き直す。
  - 写真
  - ユーザー ID
  - 連絡先(任意)
  - 使用データ

## 8. 進め方(この 順で)

1. **設計の 報告**(コードを 書く前に):
   - 1章の 構成で 進めて よいか
   - 今の CloudKit の 本番データが あるか
   - Firestore の 項目
   - ルール
