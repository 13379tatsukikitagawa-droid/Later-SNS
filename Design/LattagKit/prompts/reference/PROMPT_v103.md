## 0. なぜ 作りなおすか(調べて わかった こと)
- 1対1チャット(`DirectMessage`)・ 友だち申請(`ConnectionRequest` / `ConnectionResponse`)・ `Friendship` は CloudKit の **公開DB** に あり、`GRANT READ TO "_world"`。公開DBの 権限は **型ごと**にしか 決められず、「この 2人だけ 読める」が 作れない。→ **本文 ・ 名前 ・ 関係が だれにでも 読める**。
- 「友だちの 写真を 見る」しくみは **まだ ない**(写真が 人に 届くのは グループ ・ Trip の 共有ゾーン(CKShare)だけ)。
- CKShare は 1つの 共有に **100人まで** + 友だちに なる たびに 受け入れが 要る → 「友だちは 無制限」に 合わない。

## 8. 0 の 結果と 決定(2026/11/19)
### 8-1. 構成(Claude Code の 案を うけいれる)
- **別の Worker `server/social-worker`**(Mondo の Worker には 入れない:秘密が ちがう ・ 定期実行が ちがう ・ 無料プランの CPU 上限を 取り合わない)。
- データベースは **D1**(友だち ・ 申請 ・ 7日分の 投稿 ・ 会話 ・ ブロック)。KV は 使わない。
- 写真:**R2(公開しない)**・ アップロードは Worker 経由 ・ 配るのは **期限 15分の 署名つき URL**(Worker が 友だちか 確かめてから 出す)・ `MondoImageSanitizer` を 流用 ・ サーバーでも EXIF を 取る。
- 7日で 消す:**3つ 重ねる**(R2 の 自動削除 + 1時間ごとの 定期実行で 行を 消す + 読む 時も 7日以内だけ)。
- 置きかえる 範囲:`FriendRequests` ・ `FriendCloud` ・ `DirectMessages` の 3つ。`UserDirectory` に `firebaseUID` を 1項目 足す(**Production に Deploy が 要る**)。グループ ・ Trip ・ Mondo には さわらない。
- **1対1チャットは 5秒ごとの 読みを やめる → 15秒 + 差分だけ**(無料枠が すぐ なくなる)。
- 古い データ(友だち ・ 申請 ・ チャット)は **テスト用なので 捨てる**。
- 費用:毎日 使う 人が 約 2,000人までは 0円の 見込み(Claude Code の 見積もり)。**R2 だけ 無料枠を こえると 請求され 上限が 付けられない** → 予算アラート($5 と $20)。有料プランに したら Workers の Spend limit も。
### 8-2. グループの 招待の 穴(**先に 直す**)
- 今:グループの 共有リンクは「リンクを 知って いれば だれでも 入れる」(`publicPermission = .readWrite`)で、そのリンクを 持つ `GroupInviteCard` / `GroupInvite` が **公開DB で 世界に 読める**。→ **だれでも グループに 入れて しまう**。
- 直す:
  1. **共有リンクを 公開DB に 置かない**。友だちへの 招待カードは **Worker が 招待された `uid` の 人にだけ 渡す**(受け取った 本人が OK して 初めて 入る = 11月の 決定どおり)。
  2. **KEY(`#maple24` の 形)の 引き当ても Worker 経由**にし、**回数の 制限 ・ 期限 ・ 推測しにくい 長さ**を つける(公開DB の まま だと、短い KEY は 総当たりで 当てられる)。見た目の 形を どこまで 保つかは **0 の 続きで 相談**。
  3. 招待が なくなる 暫定:友だち カードの 招待は 止め、QR / KEY だけ 残す(直る まで)。
- **段階の 順番を かえる**:**A → A2(招待の 穴)→ B → C → D → E**。外の テスターに 配る **前に** A2 まで。

### 8-3. 順番と KEY の 形(2026/11/19 続き ・ 0 の 報告を うけて)
- **順番は (a)**:**P44(v101 ・ 案1 = Apple も Firebase に のせる)→ A → A2 → B → C → D → E**。A2 は A の Worker(`uid` の 検証)が 要るので P44 の あと。
- **外の テスターに 配るのは A2 が 終わって から**。それまでは クラスメイトなど 身近な 人だけ。
- **KEY の 引き当ての 穴**:今の `invite.ts` の「5分に 5回 ・ 7日の 期限」は、`GroupInvite` が 公開DB で `_world` 読みだと **CloudKit を 直接 読まれて すり抜けられる 可能性が 高い**(確かめる)。→ **KEY と 共有リンクの 対応は Worker の D1 だけに 持ち、公開DB の `GroupInvite` / `GroupInviteCard` は 作らない**(今ある 記録も 消す ・ `_world` 読みを 外す)。
- **KEY の 形**:見た目は **`#maple24` の まま**。中身を 強くする:
  - ことばの 一覧を 大きく(1,000語 以上)。
  - **有効は 24時間**(作った 人が 更新できる)。
  - **キーごとの まちがい 回数の 上限** + IP ごとの 制限。
  - **QR と リンクの 中身は 長い ランダムな トークン**(KEY では ない)。KEY は 口で 伝える 時の 便利な 近道。
- **友だち カードの 招待**:A で 友だち(`uid`)が できて から、Worker が **招待された `uid` の 人にだけ** 渡す(受け取った 本人が OK して 入る)。それまでの 暫定:友だち カードの 招待は 止める(QR ・ KEY は のこす)。
